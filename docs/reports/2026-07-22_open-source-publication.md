# YiW 开源发布处理报告

日期：2026-07-22

## 结论

YiW 以 `vibeinging/yiWork` 作为公开目标仓库。目标仓库已经公开，使用 MIT 许可证，默认分支 `main` 受保护。

当前本地工程来自另一段 Git 历史，并且工作区包含大量尚未提交的产品改动。为避免把旧工程历史、业务数据和未确认许可的二进制一起公开，本次发布使用目标仓库 `main` 作为基线，生成独立的干净源码快照。

发布分支：`feature/yiwork-app`。

在更新默认分支前，原 `main` 已保存在 `archive/main-before-yiwork-2026-07-22`，两者当时都指向提交 `de888ff6cf4742c35195d7e54fe5be27bc0da749`。该分支用于查看或恢复迁移前的公开版本。

## 公开内容

- Electron、Renderer、Server 和通用 Eval 源码。
- Agent、小程序、Skill、MCP、数据工作台和 Trace 优化逻辑。
- 当前设计、规格、调研和可公开测试报告。
- MIT 许可证、README、贡献说明、安全说明、第三方代码说明和基础 CI。
- 面向开源用户重新整理的 README，明确说明主 Agent、小程序、Skill 和三种更新路径。

## 排除内容

- 证券业务样例数据和相关内部评测报告。
- VexDB 本地扩展二进制；其再分发许可尚未在仓库中确认。
- vendored pi 中的 `doom-overlay` 示例和相关图片，避免把 GPL 示例混入默认 MIT 快照。
- `.env`、本地数据库、日志、构建结果、依赖目录和个人配置。
- 旧 `YiYi` 仓库历史；公开分支只继承 `yiWork` 的公开历史。

## 安全修正

- 移除了 `server/scripts/init_local_db.mjs` 中写死的内网地址、账号、密码和个人文件路径。
- 数据库连接改为使用 `SRC_DB_*` 环境变量，默认只指向本机 PostgreSQL。
- KDD 数据集路径改为 `YIW_KDD_ROOT` 或仓库内可选目录，不再包含个人机器路径。
- 增加 `.env` 和可选向量扩展二进制的忽略规则。
- 将锁文件中的 cnpm 镜像地址统一改为官方 npm registry，保证公开 CI 可以从干净环境安装。
- 恢复 macOS、Ubuntu、Windows 三平台必需检查，并修复 Windows 下 npm 启动和 SCSS 路径问题。
- 根据首次 CodeQL 扫描，收紧 Mermaid 安全级别，改用结构化 HTML 文本提取，并停止输出本机目录和数据库路径。

## 后续规则

1. 新功能从公开仓库分支继续开发，不再把旧历史直接推入公开仓库。
2. 业务数据、内部评测结果和无明确许可证的二进制默认不公开。
3. 每次合并前运行密钥扫描、许可证检查和 `npm run check`。
4. `main` 通过受保护分支的合并流程更新，不直接强推。

## README 产品定位更新

README 的产品叙述统一为三层：

1. YiW 首先是基于 pi Agent 的通用 Agent 应用底座。
2. 在通用底座之上，YiW 提供受控的自进化 Agent 框架。
3. 用户需求和可选 Skill 最终通过小程序固定为可长期使用、可交互、可升级的产品。

小程序统一定义为“App 的可安装功能单元，也是 YiW 自我生长的基本单位”。自进化不表示 Agent 可以静默修改核心 App；新增能力仍需经过检查、预览、权限确认和版本管理。Skill 与小程序保持多对多关系，用户需求可以不经过 Skill 直接生成小程序，小程序也只有在用户明确发布能力后才会成为主 Agent 可调用的 Skill。

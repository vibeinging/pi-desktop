# Skill Product 实现评审与优化报告

日期：2026-07-22

## 结论

原实现已经打通“Skill 快照、动态页面、安装、版本、Agent 工作台”的主链，但评审发现四个会破坏产品边界的问题：工具白名单可绕过、项目权限不会及时回收、产品会话会混入普通对话、草稿可移除产品绑定后继续安装。

本轮已完成修复，并补上 workflow 真实执行适配、多页面数据隔离、会话恢复和幂等冲突检查。当前基础可以继续承载不同 Skill 产品，不再只是演示路径。

## 已修复问题

### 1. 工具白名单绕过

原来产品仍暴露 `use_skill`。如果模型调用一个不存在的 Skill，当前 Skill 会被清空，后续工具调用不再受 `allowed_tools` 限制。

修复后，固化产品不注册 `use_skill`，元工具只保留 `update_plan`。当前 Skill 在整轮运行中不可切换。

### 2. 项目权限未实时检查

原来只检查模块和会话归属，没有检查用户是否仍是项目成员。用户离开项目后，已经安装的产品仍可能继续访问项目数据。

修复后，创建项目会话、创建项目型产品和每次产品运行都会检查 `project_members`。权限被移除后立即拒绝访问。

### 3. 产品会话与普通会话混用

原来产品会话使用 `agentic_chat`，会出现在普通工作台历史中，也能脱离产品版本继续运行。

修复后，产品会话使用 `skill_product` 类型。服务端要求产品请求和产品会话严格配对，普通入口不能继续产品会话。服务端同时返回当前版本最近会话，本地缓存丢失后仍可恢复。

### 4. 草稿绑定可以被剥离

原来只在 manifest 存在 `product` 时检查绑定。编辑草稿移除 `manifest.product` 后，可以通过普通模块检查，但安装事务仍会把数据库中的 Skill binding 提升为正式绑定。

修复后，只要草稿存在 Skill binding，就必须保留匹配的 manifest、权限和 `AgentWorkspace`，并且一个版本只能有一个绑定。

### 5. workflow 只是提示词模拟

原来 workflow 被改成 prompt 运行，无法保证 JSON 输出合同，也无法固化没有 `allowed_tools` 的内置 workflow Skill。

修复后，workflow 产品固定使用内部 `run_skill_workflow` 工具，直接执行安装时的 Skill 快照并保留 JSON 输出合同。

### 6. 多页面共享错误数据

原来只加载入口页的 `data/mockData`，切换到其他页面仍读取入口页数据。

修复后，每个页面拥有独立初始数据和动作结果；切换页面会执行该页面自己的 `onLoad`。

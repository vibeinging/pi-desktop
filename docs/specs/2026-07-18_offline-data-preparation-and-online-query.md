# 离线数据准备与在线问答边界

日期：2026-07-18

## 目标

YiW 把数据准备和用户问答拆成两条独立链路。

- 离线链路负责把原始来源处理成稳定、可检查、可重复使用的项目内容。
- 在线链路把已经生成的 Schema、Markdown 和数据源清单作为事实来源，同时可以在项目工作区编写代码、运行数据处理、执行查询并回答用户。
- 在线问答不自动重建 Schema、不自动转换文档、不自动补描述，也不等待后台准备任务。任务需要的代码、脚本和输出文件可以写入工作区。
- Agent 不使用 `complete_sql`、`complete_doc` 或通用 `complete` 工具结束任务。

## 离线数据准备

离线准备由导入、同步、后台任务和用户编辑触发，不由一次问答触发。

### 结构化数据

1. 登记原始文件或数据库连接。
2. 导入文件到本地 DuckDB，或从外部数据库内省结构。
3. 写入表、字段、行数和来源信息。
4. 立即生成一份基础 Schema SQL，让原始数据进入 `queryable_raw`。
5. 后台补充示例值、枚举、描述和已知关系。
6. 重新生成 Schema SQL。
7. 所有必需步骤成功后进入 `context_ready`；任一步失败都保留基础 Schema，并记录真实错误。

### 非结构化数据

1. 保存原始文件和来源信息。
2. 文本类文件本地转换为 Markdown。
3. 图片、扫描 PDF 按用户配置使用 OCR 或视觉模型。
4. 保存 Markdown、原始页码/章节等位置和转换信息。
5. Markdown 可读取后进入 `context_ready`。
6. 转换失败时保留原文件和错误，允许重新处理。

### 离线状态

状态必须区分：

- `importing`：原始内容尚未完成。
- `queryable_raw`：数据已经能查，说明内容可能还在准备。
- `context_ready`：在线问答需要的 Schema 或 Markdown 已准备完成。
- `failed`：准备失败，但不能抹掉仍可查询的原始数据或上一版内容。

后台任务内部有任一步失败时，任务不能标成 `completed`。App 重启后，未结束的结构化和非结构化准备任务都要续跑，或在达到重试上限后明确失败。

## 在线问答

在线链路从 WorkspaceAgent 委派任务开始：

```text
WorkspaceAgent
  -> QueryAgent(task packet)
      -> 读取本轮数据源/文档清单
      -> read / grep / ls / find 搜索离线产物和项目文件
      -> 可选 write / edit / bash 编写并运行处理代码
      -> execute_sql 执行只读查询
      -> 可选 format_result
      -> 输出最终消息
```

在线链路允许：

- 读取数据源和文档状态清单；
- 用 `read/grep/ls/find` 搜索、读取 Schema SQL、Markdown 和项目文件；
- 用 `write/edit/bash` 编写并运行代码、生成任务输出；
- 执行只读 SQL；
- 把多数据源结果写入会话中间库；
- 根据真实错误修改 SQL；
- 请求用户澄清；
- 生成表格或图表；
- 返回带证据的自然语言答案。

在线链路禁止：

- 未说明目的便自动重新生成或覆盖 Schema、Markdown 和数据源清单；
- 运行字段描述、表描述或关系推断任务；
- 转换 PDF、DOCX、图片等原始文件；
- 修改导入状态；
- 因为后台准备未完成而无限等待；
- 使用题型关键词正则替模型判断用户意图。

如果内容仍在准备或已经失败，QueryAgent 从清单中看到真实状态。它可以使用已有基础 Schema 查询，也可以明确告诉用户缺少哪部分内容。

## WorkspaceAgent 交接

WorkspaceAgent 继续拥有委派权。服务层不能把它决定的任务替换成当前轮原文。

交接内容使用一个小型任务包：

- `question`：要解决的完整任务；
- `resolved_context`：从历史对话中已经确认的指代和口径；
- `answer_requirements`：需要的列、格式、排序、并列和展示要求；
- `source_hints`：已经确认的数据源，可为空；
- `presentation_hint`：可选展示偏好。

这些字段只帮助 QueryAgent 保留意图，不限制它继续搜索项目内容。

## Agent 完成协议

工具只产生证据，不负责结束任务。

### 正常完成

1. QueryAgent 在 pi-agent 原生函数调用循环中工作。
2. 需要数据时调用文件、SQL、网络或展示工具。
3. 工具结果回到模型上下文。
4. 模型认为任务已解决时，不再调用工具，输出最终消息。
5. 运行时收到 `stopReason=stop` 和非空可见答案后，任务完成。

不再注册：

- `complete_sql`
- `complete_doc`
- `complete_query`
- 任何只为终止循环存在的工具

### 运行时检查

运行时只检查通用事实：

- 是否有非空最终答案；
- 是否被取消、超时、达到模型轮数上限或模型报错；
- 工具调用、SQL、中间表和引用是否完整记录在 trace 和 artifacts 中。

运行时不根据“项目里是否存在数据库”决定完成方式，也不使用“最低、最高、哪个、多少”等题型正则拦截答案。

SQL 查询的正确性由真实执行结果、Schema 证据和模型循环共同保证。文档问题由真实文件内容和引用保证。混合问题可以同时使用两类证据，不需要选择一个专用完成工具。

## 在线工作区

运行时先检查现有状态，在内存中生成数据源清单。这个检查过程本身只读；随后 Agent 的代码工作区可以按审批设置写入。清单至少包含：

- `source_id`
- 名称和类型
- SQL 方言
- Schema/文档路径
- `raw_status`
- `content_status`
- 错误或提示

文档清单必须列出所有登记文档，包括处理中和失败文档，至少包含：

- 文档 ID、标题和描述
- 状态
- Markdown 路径
- 错误

清单直接进入本轮模型上下文，不写 `SOURCES.md` 或 `DOCUMENTS.md`。缺失或过期的 Schema 只能在清单中显示，不能在问答请求里偷偷重建。

## 验收

- QueryAgent 工具列表中不存在 `complete_sql`。
- QueryAgent 注册 `read/grep/ls/find/write/edit/bash`，不再注册 `bash_readonly`。
- `ask` 模式下 `write/edit/bash` 需要确认，`auto` 模式下 `bash` 需要确认，子 QueryAgent 使用与 WorkspaceAgent 相同的审批回调。
- 有数据库的项目也能自然完成纯文档问题。
- SQL 问题在最后一次查询成功后能直接输出自然语言答案。
- QueryAgent 停止时没有可见答案，仍明确上报停止原因、模型轮次和错误。
- 在线检查工作区不会创建目录、写清单或调用 Schema 写入函数。
- 结构化导入会先生成基础 Schema，再异步补充内容。
- 后台富化内部任一步失败时任务标成失败，并保留已有 Schema。
- App 重启会续跑未结束的结构化准备任务。
- 本轮数据源和文档清单能显示准备中、失败、缺文件和可用状态。
- 不再通过题型关键词正则决定 SQL 聚合或最终列。

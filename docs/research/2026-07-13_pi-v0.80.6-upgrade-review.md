# pi v0.80.6 升级评估与实施记录

日期：2026-07-13

## 结论

PI Desktop 升级前固定使用 `earendil-works/pi` `v0.79.6`，commit 为 `31bfb2f16f7a1dd707876e970f0f80caa61f8435`。本次已升级到 [`v0.80.6`](https://github.com/earendil-works/pi/releases/tag/v0.80.6)，commit 为 `2b3fda9921b5590f285165287bd442a25817f17b`。

本次直接升级到 `v0.80.6`，没有停在中间版本，也没有跟随当时的 `main`。评估时上游 `main` 还比 `v0.80.6` 多 15 个未发布提交。

版本差距有三种算法：

| 口径 | 差距 | 说明 |
|---|---:|---|
| Git tag | 11 个 | `0.79.7` 至 `0.79.10` 共 4 个，`0.80.0` 至 `0.80.6` 共 7 个 |
| GitHub Release | 10 个 | `v0.80.4` 有 tag 和 changelog，但没有单独的 Release 页面 |
| npm 已发布包 | 9 个 | `v0.80.0`、`v0.80.4` 没有发布到 npm |

本项目保存的是上游源码，所以升级评估按 11 个 tag 计算。

## 实施结果

已完成以下工作：

- 同步 `tui`、`ai`、`agent`、`coding-agent` 四个包和根 `tsconfig.base.json`。
- 将旧全局 API 导入切换到 `@earendil-works/pi-ai/compat`。
- 将 DashScope/OpenAI compatible 缓存 token 补丁迁到 `ai/src/api/openai-completions.ts`，并保留上游 reasoning token 统计。
- 保留本地 `undici 8.7.0`，同步更新 server lockfile 和 coding-agent shrinkwrap。
- 桌面端用量归一化新增 `reasoning_tokens`，reasoning 仍是 output 的子集，不重复加入 total。
- pi 构建改为先清理四个可再生的 `dist`，避免旧版 provider 文件混入安装包；coding-agent 运行资产会重新复制。
- 新增升级契约测试，覆盖 `/compat`、Agent 生命周期、七个 coding tools、三种 API 映射、缓存和 reasoning 用量。

这次没有修改数据库 schema。已有 SQLite 数据和线性 JSONL 会话不需要迁移。

## 升级时确认的兼容情况

### 已处理的接口调整

升级前，`server/src/engine/agents/pi_runtime.js` 从 `@earendil-works/pi-ai` 根入口导入 `registerBuiltInApiProviders` 和 `streamSimple`。从 `v0.80.0` 开始，这两个接口位于 `@earendil-works/pi-ai/compat`。现在已经切换到 `/compat`，避免服务启动时报 named export 错误。

`Type` 仍从根入口导入，`Agent`、现有事件、审批钩子和七个 `create*Tool` 的调用方式在 `v0.80.6` 仍兼容。后续可单独迁到新的 `createModels()` 和 provider factory，不与本次 vendor 升级混在一起。

### 两个本地补丁仍要保留

1. OpenAI compatible 缓存 token 补丁尚未进入上游。`v0.80.6` 和评估时的 `main` 仍不识别 DashScope 的 `cache_creation_input_tokens`、顶层 `cache_input_tokens` 等字段。补丁和测试已经迁到新的 `ai/src/api/openai-completions.ts`，同时保留上游新增的 reasoning token 解析。
2. 上游 `coding-agent` 的 `undici` 从 `8.3.0` 升到 `8.5.0`，本地继续保留 `8.7.0`，没有随上游降级。

### 不需要迁移数据库和已有会话

PI Desktop 使用自己的 SQLite 和线性 JSONL 会话文件，没有调用上游 `SessionManager`。这次升级不会自动修改数据库 schema，也不会要求迁移已有对话历史。上游消息用量只新增可选的 `reasoning` 字段，旧消息仍可读取。

### 新模型不会自动出现在桌面界面

PI Desktop 从自己的模型表读取配置，并在 `buildPiModel()` 中创建模型对象，目前固定 `reasoning: false`。因此升级后可以获得 Provider 修复，但 GPT-5.6、Claude Sonnet 5 和 `max` thinking 不会自动出现在桌面模型配置中。要暴露这些能力，需要另行扩展模型配置字段和界面。

## 已执行的升级步骤

1. 同步 `v0.80.6` 的 `tui`、`ai`、`agent`、`coding-agent` 四个包和根 `tsconfig.base.json`。
2. 将旧全局 API 导入切到 `@earendil-works/pi-ai/compat`。
3. 把缓存 token 补丁和测试迁到新的 `ai/src/api/openai-completions.ts`。
4. 保持 `undici 8.7.0`。
5. 重建 `server/package-lock.json` 和四个包的 `dist`。
6. 更新 `server/vendor/README.md`、README、架构文档和第三方来源中的版本与 commit。
7. 运行服务端测试、根目录完整检查和 Electron 打包验证。
8. 将迁到新的 `Models` 结构、`max` thinking 和新模型配置留作后续独立改动。

## 验证结果

- `pi-ai` 定向缓存测试：44/44 通过。
- `pi-agent-core`：180/180 通过；coding-agent 工具与 max thinking：76/76 通过；TUI 测试通过。
- `pi-ai` 完整测试包含真实 Provider 和 Ollama 下载，不作为本项目的离线检查入口；运行时发现会拉取 13GB 模型后已中断，未继续下载。
- Server 测试：25/25 通过，其中包含 5 个新的升级契约测试。
- Renderer 测试：15/15 通过；类型检查和构建通过。
- 根目录 `npm run check` 通过。ESLint 仍有 12 个已有的 Fast Refresh 警告，没有 error。
- `npm run package:dir` 通过，`better-sqlite3` 已按 Electron 42.4.1 / arm64 ABI 重建。
- 打包产物使用临时 HOME 实际启动成功，后端进入 IPC ready；新库 `user_version=2`，与升级前 schema 一致。
- 隔离 UI smoke：1/1 通过。
- 四个包可从干净 `dist` 重建，旧 `dist/providers/openai-completions.js` 没有进入安装包。
- 与 `v0.80.6` tag 对比，仅保留缓存源文件与测试、`undici 8.7.0` package 和 shrinkwrap 四处预期差异。
- 生成的 `dist`、DOOM 示例和其他被排除的第三方二进制不进入 Git。

本地验证使用 Node.js `22.23.1`。项目已提供 `.nvmrc` 和 `.node-version`；切换 Node 主版本后需要重新安装 Server 依赖，不能复用旧 ABI 的 `better-sqlite3`。
